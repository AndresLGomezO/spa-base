# 10.8 DYNAMIC ENTITY BUILDER — IMPLEMENTATION PLAN

---

# 1. PURPOSE

The Dynamic Entity Builder allows **tenant administrators to create, modify, and manage data models at runtime**, without writing code.

It enables:

* Creation of custom entities (e.g., Loans, Contracts, Assets)
* Definition of fields and relationships
* Immediate availability of:

  * APIs
  * UI views
  * RBAC integration

This is the core capability that transforms the platform into a **no-code / low-code system builder**.

---

# 2. GOALS

### Primary Goals

* Allow tenants to define entities via UI
* Store entity definitions as data
* Dynamically register entities at runtime
* Integrate seamlessly with:

  * Query Engine
  * Relational Data System
  * UI Builder
  * RBAC

### Non-Goals

* No arbitrary scripting inside entities
* No breaking changes to existing data
* No cross-tenant entity sharing (initial version)

---

# 3. CORE CONCEPT

Entities exist in two forms:

## 3.1 Static Entities (Code-Based)

* Defined by developers
* Example: users, roles

## 3.2 Dynamic Entities (Runtime)

* Defined by tenants
* Stored in database
* Loaded dynamically

👉 Both must behave identically in the system

---

# 4. SYSTEM ARCHITECTURE

---

## 4.1 System Entity: `entity_definitions`

This stores all dynamic schemas.

### Structure

```ts
type EntityDefinitionRecord = {
  id: string;
  tenantId: string;

  name: string;
  label: string;

  fields: FieldDefinition[];
  ui?: EntityUIConfig;

  version: number;
  createdAt: timestamp;
  updatedAt: timestamp;
};
```

---

## 4.2 Field Definition

```ts
type FieldDefinition = {
  name: string;
  type: "string" | "number" | "boolean" | "date" | "relation" | "enum";

  required?: boolean;

  relation?: {
    target: string;
    type: "many-to-one" | "one-to-many" | "many-to-many";
  };

  enumValues?: string[];

  ui?: FieldUIConfig;
};
```

---

## 4.3 Runtime Entity Registry

At runtime:

1. Load static entities (code)
2. Load dynamic entities (DB)
3. Normalize both into a unified format
4. Register in a single **Entity Registry**

# 5. ADMIN UI — MODEL BUILDER

---

## 5.1 Entry Point

Admin Dashboard → “Data Models” → “Create Model”

---

## 5.2 Create Model Flow

### Step 1: Basic Info

* Name (internal): `loan`
* Label (UI): `Loans`

---

### Step 2: Define Fields

UI allows adding fields:

| Field Name   | Type     | Options           |
| ------------ | -------- | ----------------- |
| amount       | number   | required          |
| interestRate | number   |                   |
| borrower     | relation | target: user      |
| status       | enum     | Pending, Approved |

---

### Step 3: Review & Save

* Validate schema
* Confirm creation

---

## 5.3 Edit Model

Allowed changes:

* Add new fields ✅
* Update UI metadata ✅

Restricted:

* Rename fields ❌ (requires migration)
* Delete fields ❌ (soft-deprecate instead)

---

# 6. RUNTIME BEHAVIOR

---

## 6.1 On Create Entity

1. Validate schema
2. Store in `entity_definitions`
3. Rebuild entity registry (or update cache)
4. Register:

   * CRUD API
   * UI views
   * RBAC defaults

---

## 6.2 Immediate Availability

New entity becomes:

* Accessible via API:

  * `/loans`
* Visible in UI:

  * Table view
  * Create form
* Queryable via Query Engine

---

# 7. DATA STORAGE STRATEGY

---

## 7.1 Collection Naming

```ts
collection = `${tenantId}_${entityName}`
```

Example:

```
tenantA_loans
```

---

## 7.2 Schema Enforcement

* Validation via dynamic Zod schemas
* Generated at runtime from entity definition

---

# 8. INTEGRATION POINTS

---

## 8.1 Query Engine

* Must support dynamic entities
* Field validation must use runtime schema

---

## 8.2 Relational Data System

* Relation fields must resolve correctly
* Validate referenced entity exists

---

## 8.3 UI Builder

* Generates views/forms from dynamic metadata

---

## 8.4 RBAC

* Default permissions created per entity:

  * loan.read
  * loan.create
  * loan.update
  * loan.delete

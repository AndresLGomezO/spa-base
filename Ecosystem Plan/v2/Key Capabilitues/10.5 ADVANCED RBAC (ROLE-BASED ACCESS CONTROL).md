# 10.5 ADVANCED RBAC (ROLE-BASED ACCESS CONTROL) — IMPLEMENTATION PLAN

---

# 1. PURPOSE

The Advanced RBAC system controls **who can access what**, at every level of the platform.

It provides:

* Fine-grained permissions
* Dynamic, condition-based access
* Full integration with entities, UI, APIs, and hooks

---

# 2. GOALS

### Primary Goals

* Enforce secure, tenant-isolated access control
* Support dynamic entities and fields
* Enable both role-based and condition-based permissions
* Integrate with all system layers

### Non-Goals

* No hardcoded permissions per entity
* No bypass of RBAC via internal APIs
* No global shared roles across tenants (v1)

---

# 3. CORE CONCEPTS

---

## 3.1 Permission Structure

Permissions follow a consistent format:

```text
<entity>.<action>
```

### Examples

```text
loan.create
loan.read
loan.update
loan.delete
loan.approve
```

---

## 3.2 Actions

| Action | Description             |
| ------ | ----------------------- |
| create | Create records          |
| read   | View records            |
| update | Modify records          |
| delete | Remove records          |
| custom | Domain-specific actions |

---

## 3.3 Roles

Roles are collections of permissions.

Examples:

* Admin
* Manager
* Analyst
* Viewer

---

# 4. DATA MODEL

---

## 4.1 `roles` Collection

```ts
type Role = {
  id: string;
  tenantId: string;

  name: string;
  description?: string;

  permissions: Permission[];

  createdAt: timestamp;
};
```

---

## 4.2 Permission Object

```ts
type Permission = {
  resource: string; // e.g. "loan"
  action: string;   // e.g. "read"

  conditions?: Condition[];
  fields?: FieldPermission[];
};
```

---

## 4.3 Field-Level Permissions

```ts
type FieldPermission = {
  field: string;
  access: "read" | "write" | "none";
};
```

---

## 4.4 Conditions (ABAC Layer)

```ts
type Condition = {
  field: string;
  operator: "eq" | "neq" | "gt" | "lt" | "in";
  value: any;
};
```

---

# 5. ACCESS CONTROL LEVELS

---

## 5.1 Entity-Level

Controls access to entire entity:

```text
loan.read
loan.create
```

---

## 5.2 Record-Level (Conditional)

Example:

```text
User can only see loans where:
loan.ownerId == currentUser.id
```

---

## 5.3 Field-Level

Example:

* amount → read/write
* interestRate → read only
* internalNotes → none

---

## 5.4 Action-Level

Custom actions:

```text
loan.approve
loan.reject
```

---

# 6. RBAC ENGINE

---

## 6.1 Authorization Flow

```text
1. Request received
2. Identify user + roles
3. Resolve permissions
4. Evaluate conditions
5. Enforce field restrictions
6. Allow or deny
```

---

## 6.2 Evaluation Function

```ts
function authorize(user, action, entity, data?): boolean
```

---

## 6.3 Field Filtering

Before returning data:

```ts
function filterFields(data, permissions)
```

Removes unauthorized fields.

---

# 7. CONDITION ENGINE

---

## 7.1 Dynamic Context

Conditions can use:

* currentUser.id
* tenantId
* record fields

---

## 7.2 Example

```ts
{
  field: "ownerId",
  operator: "eq",
  value: "$currentUser.id"
}
```

---

## 7.3 Evaluation

* Replace dynamic variables
* Evaluate against record
